### EXIF UserComment 解码（手动 TIFF 解析）

`read_user_comment` 命令使用手动 TIFF/EXIF 解析，不依赖 kamadak-exif 库：

1. `find_tiff_block()` — 定位 TIFF 数据块：JPEG（APP1 Exif 段）、PNG（eXIf chunk）、WebP（RIFF EXIF chunk）、原始 TIFF 文件，以及全文件 fallback 扫描
2. `manual_read_user_comment()` — 解析 IFD0 和 ExifIFD（tag 0x8769），查找 UserComment tag（0x9286）
3. `extract_usercomment()` — 提取值：检测 8 字节编码前缀（ASCII/UNICODE/JIS），尝试 UTF-8 → UTF-16LE → Latin-1 降级
4. 字节序：根据 TIFF 头部的 II（LE）或 MM（BE）自动切换

**编码检测优先级**：
1. UTF-8（优先尝试，大部分 ComfyUI/WebUI 输出为此）
2. UNICODE 前缀 → UTF-16LE（EXIF 标准）
3. 检测到偶数字节 + 高字节全 0 → 推测为 UTF-16LE
4. Latin-1 降级（过滤空字节）

### 配置持久化

- 配置文件路径：`exe 所在目录/config-user.yaml`
- 格式：YAML
- 启动时自动加载，设置变更后 500ms 防抖自动保存
- `filterRegex` 不参与持久化（保存时排除，加载时忽略），避免筛选框空但实际有筛选的歧义

### 用户数据持久化（data-user.yaml）

- 数据文件路径：`exe 所在目录/data-user.yaml`（与配置分开存储）
- 格式：YAML
- 存储内容：最近访问记录（`folders` / `files`，最新在前，上限 20 条）
- 启动时 `loadRecent()` 加载，记录变更时 `saveRecent()` 保存
- 记录时机：打开文件夹/图片对话框、拖放、命令行参数、点击「最近」打开

### 图片处理流程

#### 全量扫描（refreshFolders / 旧流程）

```
文件夹选择 → Rust scan_folders
  → WalkDir 递归遍历
  → 过滤支持的图片格式
  → 读取尺寸(imagesize)、修改时间
  → 返回 Vec<ScanResult>
  → 前端一次加入 state.allImages
  → buildFolderTree 构建树
  → GridItem 按需调用 load_image_base64
```

#### 图片按需加载（loadImageBase64）

```
GridItem IntersectionObserver 进入视口（提前 300px）
  → loadImageBase64(item, force=false)
    ├─ 有缓存 base64 → 直接返回
    ├─ 大小阈值检查（非 force 时）
    │   ├─ 超过 maxLoadSizeMB → 设置 item.error 抛错，显示跳过占位符
    │   └─ 未超过 → 继续
    ├─ 设置 item.loading = true
    ├─ invoke('load_image_base64') → Rust 读取+编码
    ├─ 成功 → 设置 item.base64，显示图片
    └─ 失败 → 设置 item.error，显示错误/跳过占位符

大图查看器 / 对比视图
  → loadImageBase64(item, loadSkippedOnView)
    ├─ loadSkippedOnView=true → force=true，跳过大小检查直接加载
    └─ loadSkippedOnView=false → 不尝试加载，显示跳过占位符
```

#### 渐进式扫描（默认流程）

```
文件夹选择 → Rust scan_folders_progressive（后台线程）
  → WalkDir 遍历，每扫完一个目录立即通过事件发送
  → 前端监听 "scan-dir-progress" 事件 → handleDirProgress()
  → 逐批加入 state.allImages → 树实时更新
  → 网格逐步渲染，图片按需加载
  → 全部完成后 emit "scan-all-complete" → handleScanComplete()
  → 自动启动文件变更监听 setupFolderWatcher()
```

### 文件变更监听流程

```
用户添加文件夹 → setupFolderWatcher()
  → Rust update_watcher (notify::recommended_watcher)
  → 递归监听所有根路径
  → 文件变更时 → 过滤支持格式 → emit "fs-changed" 事件（携带路径列表）
  → 前端累积到 pendingChanges
  → 用户点击刷新
    ├─ 有红点 → applyFileChanges(pendingChanges) 细粒度增/删/改
    └─ 无红点 → refreshFolders() 全量重扫
```

## 前端架构

### 右键菜单系统

右键菜单通过 `<Teleport to="body">` 实现固定定位渲染，所有菜单项使用 `@click` + `@click.stop` 处理点击事件，点击菜单项后自动关闭菜单，点击菜单外部区域通过背景遮罩 `@click.self` 关闭。

#### 共享右键菜单组件

`GridItem.vue` 和 `ImageViewer.vue` 的右键菜单高度相似（仅第一项不同：查看 vs 关闭），通过 **`ImageContextMenu.vue`** 共享组件复用。该组件通过 `mode` prop 控制第一项：

| 模式 | 第一项 | 对应事件 |
|------|--------|--------|
| `'grid'` | 查看 | `@view` → 父组件 emit click |
| `'viewer'` | 关闭 | `@close-viewer` → 父组件 emit close |

共享菜单项：标记子菜单（1-5级标记+取消标记）/ 复制图片 / 复制路径 / 复制为文件 / 重命名 / 另存为 / **设置为壁纸** / 元信息 / 资源管理器打开 / 默认程序打开

```vue
<ImageContextMenu
  :show="ctxMenu.show"
  :x="ctxMenu.x"
  :y="ctxMenu.y"
  :item="item"
  :imgSrc="imgSrc"
  mode="grid"   <!-- 或 "viewer" -->
  @close="closeCtxMenu"
  @view="emit('click', item)"
  @close-viewer="emit('close')"
  @show-metadata="loadMetadata"
/>
```

各组件右键菜单实现：

| 组件 | 菜单项 | 实现方式 |
|------|--------|---------|
| `ImageContextMenu.vue` | 查看(grid)/关闭(viewer) + 标记/复制图片/复制路径/复制为文件/重命名/另存为/设置为壁纸/元信息/资源管理器/默认程序打开（共享组件） | Teleport to body，自身管理所有内部操作 |
| `GridItem.vue` | 委托 `ImageContextMenu`（mode='grid'） | `@view → emit('click')` |
| `ImageViewer.vue` | 委托 `ImageContextMenu`（mode='viewer'） | `@close-viewer → emit('close')` |
| `CompareViewer.vue` | 退出/文件名显隐/坐标轴显隐/视图模式切换/复制左路径/复制右路径/复制左图片/复制右图片/左图另存为/右图另存为 | 独立 Teleport to body |
| `App.vue` main-area（内容区及左右边距） | 切换模式（仅显示非当前模式选项；标题栏右键不重复弹出；顶栏/底栏不弹出）+ 粘贴为临时分组（分组模式且剪贴板含文件）+ 文件名显隐 + 控制栏显隐 | 直接渲染 inline |
| `FolderGroup.vue` folder-header | 全选/反选/一级图片/移动/复制/修改分组名（虚拟根节点）/查看模式/选择模式/文件名/打开/复制路径/移除 | Teleport to body |

全局浏览器默认右键菜单在 `App.vue` 中通过 `document.addEventListener('contextmenu', preventCtx)` 禁用。

### 剪贴板图片复制

使用 Web Clipboard API (`navigator.clipboard.write`) 实现图片复制到剪贴板：

```
data URI → 解 base64 → Blob → 检查 MIME
  ├─ PNG: 直接 new ClipboardItem({ 'image/png': blob })
  └─ 其他格式 (webp/jpeg/...): createImageBitmap(blob) → canvas → canvas.toBlob('image/png') → ClipboardItem
```

- SVG 格式特殊处理：提取 `<svg>` 标签内容构造 `image/svg+xml` Blob
- 无需任何 Rust 依赖或插件

### 复制为文件（资源管理器粘贴）

通过 `tauri-plugin-clipboard` 插件（Rust 侧 `write_files` command，前端 `writeFiles()`）将文件路径以 `CF_HDROP` 格式写入系统剪贴板，可在 Windows 资源管理器中直接粘贴。

**菜单入口**（三处）：
- 网格右键 → 复制为文件
- 大图右键 → 复制为文件
- 选择模式 → 操作菜单 → 复制文件到剪贴板

```typescript
import { writeFiles } from 'tauri-plugin-clipboard-api'

// 单文件
await writeFiles([item.path])

// 多文件（选择模式下收集所有选中路径）
const paths = collectAllSelectedPaths()
await writeFiles(paths)
```

- 依赖 `tauri-plugin-clipboard` v2.1.11（Rust）+ `tauri-plugin-clipboard-api`（前端）
- 权限：`clipboard:allow-write-files`

### 粘贴为临时分组

读取剪贴板中的文件路径（`CF_HDROP`，即「复制为文件」写入的内容）并创建临时虚拟分组：

```typescript
import { hasFiles, readFiles } from 'tauri-plugin-clipboard-api'

// 检测剪贴板是否含文件（右键菜单打开时刷新）
const has = await hasFiles()

// 读取文件路径列表（Windows 下直接返回路径）
const paths: string[] = await readFiles()
await scanFilesAsVirtualGroup(paths)  // 复用扫描逻辑创建临时分组
```

**菜单入口**：内容区右键菜单（分组模式 且 `hasFiles()` 为 true 时显示）
**权限**：`clipboard:allow-has-files`、`clipboard:allow-read-files`

### 状态管理

使用 Vue 3 `reactive()` 全局状态对象 (`imageStore.ts`)，包含：

```
state
├── allImages          # 所有图片列表（去重）
├── loadedRootPaths    # 用户加载的根文件夹路径
├── folderTree         # 目录树结构
├── virtualGroups      # 虚拟分组列表
├── folderGroup        # 是否启用目录分组
├── showGroupTitle     # 是否显示分组标题（含虚拟分组）
├── selectMode         # 选择/查看模式
├── selectedPaths      # 选中图片路径 Set
├── selectedFolderPaths # 选中文件夹节点路径 Set（用于节点级操作）
├── settings           # 应用设置（含颜色、外部程序等）
├── loading            # 加载状态
└── cancelledRoots     # 用户取消扫描的根路径集合

rootExclusions (reactive Map)  # 根路径 → 排除子路径集合
```

### 隐私模式

隐私模式通过 `state.settings.privacyMode` 控制，开启后：

**图片显示**：GridItem、ImageViewer、CompareViewer 在加载环节检测隐私模式，跳过 `loadImageBase64`，直接使用 `PRIVACY_ICON_SRC`（内联 SVG data URL）。图片仍正常加载到缓存，关闭隐私模式后立即显示真实图片。

**节点名匿名**：FolderGroup 新增 `anonName` prop。FolderPanel 和递归渲染中按 `v-for` 序号传递 `i18n` 多语言名称（如 `"节点1"`、`"Node 1"`）。显示时优先使用 `anonName` 替代 `node.name`。

**选择/标记隐藏**：GridItem 中 `select-check` 和 `mark-badge` 在隐私模式下通过 `v-if="!state.settings.privacyMode"` 隐藏。

**实现文件**：
- `imageStore.ts` — 导出 `PRIVACY_ICON_SRC` 常量 + `ensurePrivacyIcon()` 函数
- `GridItem.vue` — `doLoad()` 中检测隐私模式
- `ImageViewer.vue` — `loadCurrentImage()` 中检测
- `CompareViewer.vue` — 图片对加载时检测
- `FolderGroup.vue` — `anonName` prop + 递归传递
- `FolderPanel.vue` — 根节点传递 `anonName`
- `SettingsPanel.vue` — 高级标签页开关

### 数据流向

```
Rust 扫描 → imageStore.scanFolders()
  → state.allImages 更新
  → setupFolderWatcher() → Rust update_watcher → 开始监听文件变更
  → FolderPanel 通过 computed 调用 buildFolderTree()
    → 根据 loadedRootPaths + rootExclusions 构建多根树
  → GridItem 按需调用 loadImageBase64()
    → Rust 返回 base64 → 显示图片
```

Ctrl+滚轮 → App.vue content-area → state.settings.gridSize 调整 → 全局格子大小变更

文件外部变更 → notify 监听 → emit "fs-changed" 事件（携带路径列表）→ state.pendingChanges 累积
→ 用户点击刷新
  ├─ 有红点 → applyFileChanges() 细粒度增/删/改
  └─ 无红点 → refreshFolders() 全量重扫

### 树构建算法

`buildFolderTree(images, rootPaths)`:

1. 按 `loadedRootPaths` 分组，每个根文件夹独立建树
2. 检查 `rootExclusions` 排除被手动删除的子路径
3. 根节点显示完整路径，子节点仅显示文件夹名
4. 虚拟分组作为根节点显示在树顶（📦 标记）
5. 没有根路径时（仅加载单图）返回空树

### 排序体系

**文件排序**（`sortImages`，作用于网格/大图组内图片）：
- 排序方式 `sortBy`：名称（`localeCompare` + `numeric: true` 自然序，与 Windows 资源管理器一致：1, 2, 11）/ 修改日期 / 文件大小
- 排序方向 `sortOrder`
- 通过 `getProcessedImages()` 统一应用（筛选 + 排序）

**分组排序**（`sortFolderNodes` / `sortFolderTree`，作用于文件夹树节点顺序）：
- 排序方式 `groupSortBy`：名称（自然序）/ 修改日期（取子树图片最大修改时间）/ 数量（含子节点图片总数）
- 排序方向 `groupSortOrder`（与文件排序独立）
- `sortFolderTree` 原地排序保持节点对象引用（避免破坏折叠/展开/路径查找）；`sortFolderTreeCopy` 返回深拷贝副本（用于 `navigableList`、`buildFullTree` 等只读消费）
- 虚拟分组不参与分组排序（保持用户创建顺序，避免导航索引错位）

**UI**：`FilterSortBar.vue` 排序区提供「文件 / 分组」作用域切换，选项随作用域变化（文件：名称/修改日期/文件大小；分组：名称/修改日期/数量），升降序按钮共用但分别读写 `sortOrder` / `groupSortOrder`

### 子节点删除机制（路径排除）

删除子节点不直接删除图片，而是将子路径加入 `rootExclusions`（该根路径的排除集）。树构建时自动跳过被排除路径的图片。

- 根节点删除：从 `loadedRootPaths` 移除，清理对应 exclusions。只删除不被其他根路径覆盖的图片
- 子节点删除：将相对路径加入父根的 exclusions。图片保留在 `allImages` 中，仍可被其他根路径引用

### 着色体系

FolderGroup 采用四层着色体系（通用逻辑，不限于彩虹模式）：

| 层级 | 元素 | 不透明度 |
|------|------|---------|
| 整体背景 | `folder-group` | 100%（直接使用 base color） |
| 标题条 | `folder-header` | transparent（依赖父级） |
| 网格包裹 | `folder-grid-wrapper` | transparent |
| 网格容器 | `grid-container`（通过 prop） | 彩虹时 100%，否则 `bgColor` |

- `getBaseColor(depth)` 统一获取基础色：彩虹模式取彩虹轮替 `colors[(depth-1) % N]`，否则取 `childTitleBgColor`
- depth=0（根节点）保持 `rootTitleBgColor`
- 颜色不足时自动轮替：1,2,3,4,5,1,2,...

### 展开状态管理

**架构**：`expandedMap`（`reactive(Map)`）存储每个节点的展开状态，首次构造时确定，用户可翻转，永不重算。

**作用域键**：虚拟分组节点与真实分组节点如果路径相同会导致折叠状态冲突。为避免此问题：

- 虚拟分组节点使用带前缀的**作用域键** `vg:${vgIndex}:${node.path}`
- 真实分组节点使用**绝对路径**（如 `E:/folders/a/pick1`）作为键，由 `FolderGroup.getExpandKey()` 计算（拼接 `rootPath` 与相对路径）
- 两者在 `expandedMap` 中互不干扰，多根文件夹下同名子目录（如 `a/pick1` 与 `b/pick1`）也不会冲突

- `FolderGroup.vue` 的 `getExpandKey()` 生成展开键：虚拟分组返回 `vg:${vgIndex}:${node.path}`，真实树返回 `getNodeAbsolutePath()`
- 模板中所有 `getExpanded(node)` 调用均显式传入 `getExpandKey()`，`handleToggle` 的 `@toggle` 事件也携带该键
- `FolderPanel.vue` 的 `isExpanded(node, key?)` 优先使用传入的 key；`toggleNode(node, scopeKey?)` 同理
- 批量操作（全部展开/折叠、折叠叶子节点、筛选展开）通过 `setAllVg()` / `collapseLeavesVg()` 递归处理虚拟分组子节点

**大文件夹自动折叠**：
- 每个根路径有独立的 `rootLargeDetected` 标志
- 节点首次构造时，通过树搜索找到所属根节点
- 若该根已标记 → 节点默认折叠
- 否则展开，然后检查根节点是否达标（>5 子文件夹 或 >100 张图）
- 达标则标记该根，当前节点也折叠
- 此后该根下所有新节点默认折叠
- `state.loading` 从 true→false 时重置所有标志

**筛选联动**：筛选变更时自动更新——有匹配的节点展开，无匹配的折叠。

### NavigableList 导航系统

大图查看器的跨节点导航（Ctrl+←/→）基于 **NavigableList** 架构实现：

**`navigableList`** (computed) — `imageStore.ts` 中维护的扁平有序列表，包含所有可导航节点：
1. 虚拟分组子节点（后序遍历：子→父）
2. 虚拟分组一级图片（最后）
3. 真实目录树节点

每条记录包含 `{ images, path, displayPath, scopeId, groupName }`，其中 `displayPath` 是层级显示路径（如 `"B / A"`），`scopeId` 用于隔离不同虚拟分组和真实树的导航边界。

**`navIndexMap`** (computed) — `Map<navKey, index>` 实现 O(1) 查找，navKey 格式：
- 虚拟分组节点：`vg:${vgIndex}:${hierarchy}`（如 `"vg:0:A"`、`"vg:0:B / A"`）
- 真实树节点：`tree:${node.path}`（`node.path` 为**绝对路径**，`navigableList` 中由 `toAbsPath(rootPath, node.path)` 拼接得到）

**导航流程**：
```
网格点击 → FolderGroup.getNavKey() 计算 navKey
         → 同时计算 imageIndex（点击图片在组内的位置）
         → emit('viewImage', item, scope, navKey, imageIndex)
         → App.vue.viewImage: navIndexMap.get(navKey) → viewingNavIndex
         → viewingImages = navigableList[viewingNavIndex].images

Ctrl+→ : viewingNavIndex++ → 检查 scopeId 是否相同（不跨组）
       → viewingImages = navigableList[viewingNavIndex].images
       → viewingIndex = 0（第一张）
       → 冒泡提示 entry.displayPath

Ctrl+← : viewingNavIndex-- → viewingIndex = entry.images.length - 1（最后一张）
```

**特性**：
- O(1) 导航，无树遍历
- 顺序与 UI 显示一致（同一 computed 数据源）；真实目录树按分组排序遍历，虚拟分组保持创建顺序
- `scopeId` 隔离虚拟分组和真实树，不跨边界
- 响应式缓存：computed 仅依赖变更时重算，仅被读取时求值
- 导航时组内图片使用 `getProcessedImages` 排序，与网格一致

### 大图分组内导航

- 分组模式下左右方向键（非 Ctrl）限于当前 `viewingImages` 范围内导航
- `viewingImages` 来自 `navigableList` 中当前 entry 的 `images`（已排序+筛选）
- 未分组模式下使用 `getProcessedImages(state.allImages)` 整体排序后的全部图片导航（与网格显示顺序一致）
